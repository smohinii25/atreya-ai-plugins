# atreya-docs layout

Organised by MODULE: everything about one module sits in one folder.

```
atreya-docs/
├── modules.yaml          single module list; every command reads it (map --merge writes it)
├── environments.md       env → ref, host, flags, integration mode. Human-filled.
├── glossary.md           domain terms (candidates marked TO CONFIRM)
├── external-systems.md   third-party systems and where code uses them
├── not-in-use.md         features/routes believed unused (Confirmed / Needs confirmation)
├── security/secret-scan.md   one-time secret scan (types and locations only)
├── _map/<repo>/          raw map output per repo (scripts, deterministic)
│   ├── modules.md  routes.md  screens.md  models.md  api-links.md
│   └── *.json            machine copies used by later scripts
├── nt/<module-id>/
│   ├── BRD.md  PRD.md
│   ├── staging-delta.md  what staging has that production doesn't
│   ├── checks/<DOC>-check.md  doc-checker reports (-2 = second pass, critical modules)
│   └── diagrams/<name>.drawio  (+ <name>.spec.json it was generated from)
├── _map/_modules/<id>/facts.md|json   fact pack the PRD/BRD are written from
└── dev/<ticket-id>/            free text without a ticket: dev/adhoc-<slug>/
    ├── impact-facts.json       single source: script facts (hashed) + Claude's analysis
    ├── impact-facts.md         the script facts, readable
    ├── impact.md               /atreya:impact, rendered from the JSON (not tracked by /atreya:sync)
    ├── impact-report.html      same data as one self-contained interactive page (offline, no external requests)
    └── checks/impact-check.md  impact-check.sh output + doc-checker report
```

Rules
- `environments.md` starts from `references/environments-template.md` with every
  value "TO FILL". Never fill it from `.env` or any secret file. Commands that need
  a repo's mapping (staging-delta) skip that repo with "waiting for environments.md".
- Nothing under `atreya-docs/` may contain a key, password or token: script output
  passes `scripts/lib/redact.sh`; anything written by hand or by Claude must too.
- Raw `_map/` files are regenerated by scripts; never edit them by hand. The
  one exception is `_map/overrides.yaml`: human-owned fixes for links the
  scripts mark "unresolved" (which page/screen triggers a call, the URL of a
  dynamic JS call). `link-apis.sh` creates it empty once, reads it on every
  run and never changes it; entries that no longer match a call site are
  listed under "Overrides that match nothing" in `_map/<client>/api-links.md`.
  `modules.yaml`, `environments.md`, glossary, external-systems and not-in-use are
  human-owned after their first draft.
- Product code is in `repos/` (read-only). Docs never copy code blocks longer than a
  few lines; they cite `repo:path:line` instead.
