# Diagram guide

Diagrams are generated by scripts from the map data, never drawn by hand, so
every teammate gets the same file and every box and arrow can be traced to code.
Output: `atreya-docs/nt/<id>/diagrams/<name>.drawio` plus `<name>.spec.json`
(the input it was rendered from). Open `.drawio` files with draw.io / diagrams.net.

| Kind | Command | Shows | Built from |
|---|---|---|---|
| ER | `make-diagram.sh <id> er` | the module's tables, columns from migrations, model relations between them | fact pack tables, `models.json` |
| Sequence | `make-diagram.sh <id> sequence --routes "POST a,POST b" --name seq-<REQ-ID> --title "…"` | screen → client caller → route → controller@method → tables, then the response with HTTP codes found in code | fact pack routes and API calls, `controllers.json` |
| Flow | `make-diagram.sh <id> flow --platform app` / `--platform web` | the module's screens and their navigation (file:line); targets outside the module as dashed "external" boxes | `screens.json` navigation |

## Default set for a module
1. `er`
2. `flow --platform app` and `flow --platform web` (skip a platform with no screens)
3. One sequence per PRD requirement that has live APIs: name it `seq-<REQ-ID>`
   (e.g. `seq-AUTH-R01`), `--routes` = the requirement's **API** line, in the
   order the user experiences them, `--title` = the requirement title. Skip routes
   the fact pack lists under "no screen calls".

## Re-running
Each `<name>.spec.json` keeps `options`: the options the diagram was made with
(routes, client, callers, name, title, platform; only those given). Refresh an
existing diagram with `make-diagram.sh <id> --rerun <name>`, which repeats its
kind and options exactly, so the same commit gives the same file. Choose new
options only for a new diagram, or when the user approves a change (e.g. the
requirement's API line changed). A spec without `options` (made before they were
recorded) is regenerated from the default set above.

## Reading a diagram
- Every box/arrow has an `atreya_source` (Edit Data in draw.io) = its citation.
- App calls are traced to a feature folder, so a sequence may start from a box
  "N screens" naming all screens in that folder.
- The footer and the `atreya-stamp` object carry module, date and commits;
  `/atreya:sync` compares them with HEAD.

## Checks
- `make-diagram.sh` runs `check-doc.sh` on each `.drawio`: well-formed XML, stamp,
  every box/arrow has a source (except external boxes), citations exist, no keys.
- Then the `doc-checker` agent verifies that each box and arrow exists in code.
- After generating, update PRD §14 to list the diagrams.
