---
name: diagram
description: Generate draw.io diagrams for one module from code (ER of its tables, screen flow per platform, one sequence per PRD requirement), with commit stamps and a doc-checker pass on every box and arrow. Run as /atreya:diagram <module-id> [er|flow|sequence|all].
argument-hint: "<module-id> [er|flow|sequence|all]"
model: sonnet
effort: low
disable-model-invocation: true
allowed-tools: Bash(bash ${CLAUDE_PLUGIN_ROOT}/scripts/*), Read, Edit
---

Arguments: `$ARGUMENTS` (default kind: all). Workspace root:
`${user_config.workspace_root}`; pass it as `--root`. Follow
`${CLAUDE_PLUGIN_ROOT}/references/diagram-guide.md`. Diagrams are generated by
scripts only: never write or edit `.drawio` or `.spec.json` files by hand.

1. Run `module-facts.sh <id>` (refreshes the fact pack).
2. **Existing diagrams first.** For every `<name>.spec.json` already in
   `atreya-docs/nt/<id>/diagrams/` (within the requested kind), regenerate it with its
   saved options: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/make-diagram.sh" --root "${user_config.workspace_root}" <id> --rerun <name>`.
   Do not re-derive its routes or callers from the PRD. If a sequence's saved routes
   differ from its requirement's current **API** line in PRD §4, list both to the
   user and ask which to use; only with approval regenerate it with new options
   (as below). If `--rerun` says the spec has no saved options, regenerate it as below.
3. **New diagrams.** Generate the ones not there yet with
   `bash "${CLAUDE_PLUGIN_ROOT}/scripts/make-diagram.sh" --root "${user_config.workspace_root}" <id> <kind> [options]`
   (the options are saved in the spec for the next run):
   - `er`
   - `flow --platform app` and `flow --platform web` (skip a platform with no screens)
   - sequences: read `atreya-docs/nt/<id>/PRD.md` §4; for each requirement with an
     **API** line, run `sequence --routes "<its routes, in user order>" --name seq-<REQ-ID> --title "<REQ-ID>: <title>"`,
     leaving out routes listed under "no screen calls" in the fact pack. If there is
     no PRD yet, make one sequence per called route group and tell the user.
   Every make-diagram run (steps 2 and 3) must end with `check-doc: PASS`; if not,
   report the failure and stop.
4. Launch the `doc-checker` agent (fresh context) on the diagrams folder
   `atreya-docs/nt/<id>/diagrams/` (all `.drawio` files, using each element's
   `atreya_source`). Save its report as `atreya-docs/nt/<id>/checks/diagrams-check.md`.
   A wrong box or arrow is fixed in the map scripts or the spec options, never by
   editing the diagram; report anything you cannot fix.
5. Update PRD §14 with a table `Diagram | Kind | Shows | File` (if PRD.md exists),
   then re-run `check-doc.sh` on the PRD.
6. Report: diagrams written (boxes/arrows each; say which were re-run from saved
   options and which are new or got new options), check results, doc-checker summary.
