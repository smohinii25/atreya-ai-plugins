# atreya-ai-plugins

Claude Code marketplace for Atreya Innovations. It holds one plugin, **atreya**
(commands appear as `/atreya:<name>`).

Version 0.2.0 has a fail-closed safety guard, a session banner, `/atreya:help`
and the docs commands below (changes: [`plugins/atreya/CHANGELOG.md`](plugins/atreya/CHANGELOG.md)). QA and dev commands are planned (listed by
`/atreya:help`).

## Docs commands

| Command | What it does | Writes |
|---|---|---|
| `/atreya:map <repo>` | Maps one repo: routes, controllers, models/tables, screens, external systems | `atreya-docs/_map/<repo>/` |
| `/atreya:map --merge` | Proposes the module list from the maps; writes it only after you approve | `atreya-docs/modules.yaml`, seed docs |
| `/atreya:link-apis [module]` | Links every web page and app screen to the backend API it calls; lists calls with no route and routes nobody calls | `_map/<repo>/api-links.*`, block in `not-in-use.md` |
| `/atreya:prd <module> [zoho-item]` | Drafts or updates a module PRD (`<MODULE>-Rnn` requirements) from code, then an independent doc-checker pass | `nt/<module>/PRD.md`, `checks/PRD-check.md` |
| `/atreya:brd <module> [zoho-item]` | Same for the BRD, in plain language (`BR-nn`) | `nt/<module>/BRD.md`, `checks/BRD-check.md` |
| `/atreya:diagram <module> [er\|flow\|sequence\|all]` | draw.io diagrams generated by scripts from code (ER, screen flow per platform, one sequence per requirement); every box cites its source | `nt/<module>/diagrams/` |
| `/atreya:impact <zoho-item \| "text">` | End-to-end impact of one change: direct and indirect modules (upstream/downstream, with the cited path), routes and callers, screens, data flow, workflow before/after, evidence-based risk, QA regression scope, open questions | `dev/<ticket>/impact.md`, `impact-report.html` (self-contained, offline), `impact-facts.json`, `checks/impact-check.md` |
| `/atreya:sync [module]` | Lists docs and diagrams that are out of date with the code (commit stamp vs `git log`); refreshes the ones you approve | approved diagrams and `staging-delta.md`; for PRD/BRD it gives you the command |

All paths are under `<workspace_root>/atreya-docs/`; the layout is in
[`plugins/atreya/references/docs-layout.md`](plugins/atreya/references/docs-layout.md).

**Typical order:** `/atreya:map` for each repo → `/atreya:map --merge` →
`/atreya:link-apis` → `/atreya:prd <module>` → `/atreya:brd <module>` →
`/atreya:diagram <module>`. Then `/atreya:impact` for each ticket, and
`/atreya:sync` after code changes.

How the docs stay honest:
- Scripts do the mapping (same commit → same output); Claude writes the prose.
- Every statement cites `Repo:path:line`, a Zoho Sprints item or a human doc;
  anything else goes to "Needs confirmation" / "Open questions".
- Each doc and diagram carries a stamp (module, date, repo commits) so `sync`
  can tell when it is out of date. Claude writes `Draft`; only a human sets
  `Reviewed` / `Approved`.
- Two checks: `check-doc.sh` (structure, IDs, citations exist, no keys) and the
  `doc-checker` agent, which re-reads the cited code in a fresh context.
  Neither is exhaustive: review the "Needs confirmation" items yourself.

## Impact analysis (`/atreya:impact`)

One run writes four files to `atreya-docs/dev/<ticket>/` (free text: `dev/adhoc-<slug>/`):

- `impact-facts.json`: the single source. Script facts (hashed, never edited
  by hand) and Claude's analysis are kept apart in it.
- `impact.md`: the 12-section document, rendered from the JSON.
- `impact-report.html`: the same data as one offline page. It has a clickable
  dependency map with search and filters, the workflow before/after, a drill-down
  per module, data flow, a risk table, QA scope, evidence and open questions.
  It makes no external requests and escapes all text.
- `checks/impact-check.md`: mechanical checks plus the independent doc-checker report.

Every finding carries an evidence class: **Verified** (`Repo:path:line`),
**Inferred**, **Assumption**, **Unknown** or **Not affected**. Every risk level
comes from a rule in `references/impact-risk-rules.md`. Indirect modules are
traced through routes and callers, shared services, changed tables and event
listeners, up to `--depth` module hops (default 3). Cycles are handled.
Nothing is ever marked Approved or "executed".

## What the guard protects

Your workspace (the `workspace_root` setting) is laid out like this:

```
<workspace_root>/
  repos/        product repos      read-only by default
  atreya-docs/  docs, QA, dev output   writable
  atreya-qa/    Playwright tests   writable
```

Every tool call is checked before it runs:
- secret files (`.env`, keystores, firebase/google-services files, ...) are never read;
- `repos/` is read-only unless a human-approved ticket and a feature branch exist;
- git is read-only;
- `php artisan` is limited to `route:list`, `list` and `about`;
- package installs are blocked in `repos/`;
- production hosts are blocked;
- Zoho Sprints changes ask you first.

Plain-English rules and known limits:
[`plugins/atreya/references/safety-rules.md`](plugins/atreya/references/safety-rules.md).

## Requirements

- macOS 15 or later (the guard uses the built-in `/usr/bin/jq` and `/bin/bash`; nothing to install)
- Claude Code (terminal, desktop app or VS Code)
- Access to the GitHub repo `smohinii25/atreya-ai-plugins`. If it is private, sign
  in first with `gh auth login` (or have an SSH key for github.com); Claude Code
  uses your existing git credentials and never prompts.

## Install (each teammate, once)

In a Claude Code session:

```
/plugin marketplace add smohinii25/atreya-ai-plugins
/plugin install atreya@atreya-ai-plugins
```

Choose **Install for you (user scope)**. Or, from your shell:

```bash
claude plugin install atreya --marketplace smohinii25/atreya-ai-plugins
```

When the plugin is enabled, Claude Code asks for its settings:

| Setting | What to enter |
|---|---|
| `workspace_root` | **Your own** workspace folder, e.g. `/Users/<you>/Mohini/atreya-ai` (default `~/Mohini/atreya-ai`) |
| `staging_url` | Staging dashboard (default `https://staging-dashboard.naditarangini.com`) |
| `staging_username` | Your staging QA login |
| `staging_password` | Your staging password. Stored in the macOS Keychain, not in `settings.json` |

## Set or change `workspace_root`

Run `/plugin`, open the **Installed** tab, select **atreya** and choose
**Configure options**. Non-sensitive settings also appear in `/config`.
Then start a new session (or run `/reload-plugins`).

Check it: every session starts with a banner such as

```
atreya v0.2.0 | workspace ~/Mohini/atreya-ai | repos read-only
```

If the path is wrong, the banner says `NOT FOUND`. Run `/atreya:help` to see
the commands.

## Run the tests

From a clone of this repo:

```bash
git clone https://github.com/smohinii25/atreya-ai-plugins.git
cd atreya-ai-plugins
bash plugins/atreya/tests/guard-tests.sh       # safety guard: PASS/FAIL per case + summary
bash plugins/atreya/tests/guard-tests.sh -v    # also print each block reason
bash plugins/atreya/tests/scripts-tests.sh     # docs scripts: map, link-apis, facts, check-doc, diagrams, impact, sync
bash plugins/atreya/tests/impact-tests.sh     # impact v2: dependency graph, risk rules, render, HTML safety (fake fixtures)
bash plugins/atreya/tests/known-answers-auth.sh  # your real workspace: auth links verified in code (after map + link-apis)
bash plugins/atreya/tests/compat-otp-example.sh  # your real workspace: the adhoc-otp-attempt-limit example still gives the same modules/routes
claude plugin validate plugins/atreya
```

The two "real workspace" tests take your workspace root as an argument when it is
not `~/Mohini/atreya-ai`, e.g. `bash plugins/atreya/tests/compat-otp-example.sh ~/work/atreya-ai`.

`known-answers-auth.sh` reads your own `atreya-docs/_map/` and skips if it is
not there. Set `ATREYA_KEEP_TEST_DIR=1` to keep the throwaway test workspace for
debugging.

The tests build a throwaway workspace in `$TMPDIR` (fake Laravel and Flutter
repos, dummy secrets, an approved ticket) and delete it afterwards; they never
touch your real repos. Each script exits with 1 if any case fails.

## Updates

Auto-update is off by default for this marketplace. To update: `/plugin`, then
**Marketplaces**, then **atreya-ai-plugins**, then **Update marketplace**. Or run
`claude plugin update atreya@atreya-ai-plugins`. You can also turn on
**Enable auto-update** there.

## For maintainers

- `plugin.json` pins `version`, so bump it (e.g. 0.1.1) on every change once
  teammates use the plugin, or they will not receive the update. Also update
  the version line in `skills/help/SKILL.md` (the banner reads `plugin.json`
  by itself).
- Scripts must run on stock macOS: bash 3.2, BSD awk/sed, `/usr/bin/jq`, git.
  No Homebrew tools. Every script takes `--root <workspace_root>` (skills pass
  `${user_config.workspace_root}`) and reads repo files only through
  `tracked_files`. A script that copies text out of repo files (messages,
  values, labels) must pass it through `lib/redact.sh`; scripts that write only
  names, counts and `file:line`, or combine already-redacted `_map` data, need not.
- Production hosts live in `plugins/atreya/config/prod-hosts.txt`, one per
  line. Never add a parent domain such as `naditarangini.com`, because it
  would also block staging.
- Before every push run `guard-tests.sh`, `scripts-tests.sh` and
  `claude plugin validate plugins/atreya`.
- The guard blocks edits to the plugin folder it is loaded from. If you test
  with `claude --plugin-dir plugins/atreya`, edit the files in a session where
  the plugin is not loaded.
